# LVS Gredwitch Effects — Changelog

## Update: "Right Barrel, Every Time"

Muzzle flashes and smoke now land on the correct gun on every vehicle,
including while driving fast and with the turret turned.

**Fixed**
- Shared-point multi-barrel mounts (Pz.IV Zerstörer, four barrels around one `aim` point) had all barrels feeding one steady-offset estimate, so flashes landed on the wrong barrel or on the aim point. Offsets are now learned per barrel (samples grouped by position).
- Twin/quad mounts picking the neighbouring barrel at speed with the turret turned (Crusader AA): the hull's one-tick origin lag runs along the line between the barrels there, and the barrel pick used the uncorrected origin. The weapon's learned tick correction is now applied before the pick.
- Flash and smoke trailing the muzzle at speed: a control point set from Lua is always a frame behind the engine's own particle update (confirmed by A/B against the engine's attachment-follow, which was clean). Followed muzzle effects now ride a hidden proxy entity parented to the vehicle root with `PATTACH_ABSORIGIN_FOLLOW`, so hull motion is engine-timed; Lua only sets the proxy's local pose (attachment transform plus the code offset, oriented by the shot). Verified in-game against the engine's own attachment-follow; the same test showed gred's unlocked flash particles trailing even on the proxy, so the locked PCF copies stay.
- Flash inside the barrel on guns whose server-side recoil is not mirrored on the client (BMP-2 30mm: the origin sits 22.6 u back down the bore while firing): any part of a gun's offset pointing back along the bore from its attachment is dropped; sideways and forward parts are kept.
- Howitzer barrel smoke left behind by the recoil (Pz.I Bison): the howitzer effect has no bullet record and its Attack code names no attachment, so the smoke was placed in the hull frame, which does not recoil. The vehicle's own `TurretBallisticsMuzzleAttachment` stands in as the weapon code for the turret-ballistics gun where it exists; where the gun's code fires from a fixed hull vector instead (the Bison — LVS's own flash does not recoil there either), the model's attachment on the shot's bore line, which sits on the gun bone, is used for that one effect. Flash and smoke ride the recoiling barrel.
- The one-tick origin correction is now decided per gun from its own shots instead of applied blindly: it removed a real 4 u lag on tank turrets but put the Willys pintle MG's flash 8 u ahead of the barrel, because different LVS fire paths differ in whether the server origin is a tick stale. The correction that leaves the smaller median offset over the recent shots is the one used.
- Flash beside the barrel while a fast mount (Willys pintle MG) is swung: the server and client smooth the mount's aim independently, so during a swing the server's shot origin sits several units off the barrel the client renders, with the swing's sign. The gun's steady offset is now learned only from shots fired with the mount at rest (attachment unmoved in hull space since the previous shot) and applied while it moves; a genuine constant offset (BMD-4M 30mm) is kept because it is present at rest too. Until a gun has fired at rest once, the flash sits on the weapon code's attachment itself rather than on the jittering per-shot origin.
- Muzzle flash sometimes turned 90 degrees from shot to shot: guns firing right at their attachment used the engine's attachment-follow, which orients the flash by the attachment's own angles (often authored along another axis), while shots a hair further away used the addon's follower oriented by the shot direction. Every flash and barrel smoke is now driven by the follower from the weapon code's attachment at the shot's exact offset, oriented by the shot direction.
- Turret traverse (T-35 and any tank whose client does not maintain LVS's `GetTurretYaw` field): the frozen reference model wrote the main turret pose from LVS's accessors, which read 0 on the client, over the pose it had just copied — so the reference turret stayed at zero while the real one turned and the flash slid off the gun shot by shot. The reference now takes every pose parameter straight from what the client renders, mapped through its range, and nothing overrides it.
- Muzzle flash smearing behind a fast vehicle: gred's Insurgency/DoI flash PCFs were made for a standing shooter and emit world-space particles, so at vehicle speed a 0.1 s flash trailed 30 u behind the barrel and its smoke was dropped in the air. The addon now ships `particles/lvs_gred_muzzle.pcf`, gred's flash definitions (children included) with a lock to the barrel control point: flash parts stay on the muzzle for their whole life, the flash's own smoke leaves with the vehicle's velocity and sheds it as it ages instead of being dropped in place. Generated by `tools/pcf_tool.py build-muzzle`.
- Flash and barrel smoke floating in the air beside a fast-moving vehicle: the muzzle effect's world origin trails the client's interpolated vehicle by speed x interpolation time, and that lag was being baked into the particle's offset. The origin now comes from LVS's own `SrcEntity` — the shot origin in the vehicle's local space computed on the server at fire time (the value LVS blends its bullets from) — which cannot lag. The muzzle effect waits one frame for its tracer record when that arrives second.
- Muzzle placement no longer searches for attachments at all. The shot origin is the weapon code's own output, so it is only ever expressed in one of two exact frames and driven from it every frame: the attachment the weapon's code fires relative to (single-barrel guns flash on the attachment itself; a barrel offset from a shared "aim" point, or a gun firing beside its named point, keeps its exact offset), or, for LVS preset weapons whose code names no attachment, the firing entity's own transform. The nearest/named/EffectData fallback chain, the per-gun memory and the world-position fallbacks are gone; barrel smoke uses the same frame as the flash.
- Muzzle flash jumping to the cannon while the T-35's turret MG fires on the move: when the weapon code's own attachment narrowly misses the barrel-line test (turret traverse puts the client's attachment a few units from where the server fired), the geometric fallback could hand the shot to a different gun 28 u away. The code's attachment now only loses to a fallback attachment that is clearly closer to the shot (`weapon_code_near`); when the code names a single point, only a muzzle/barrel-named attachment right at the shot origin (a twin/quad mount's real barrel tip) can take it, so a nearer non-barrel attachment such as the BMD-4M's misnamed "sight" never steals the 30mm's flash.
- Muzzle flash landing on the wrong gun while driving (T-35 turret MG flashing from the cannon): the shot origin comes from the vehicle's newest networked transform while the client's attachments trail it by the interpolation delay, so at speed the MG's origin was nearer the cannon muzzle than the MG. The origin is now re-expressed in the interpolated frame before matching; the debug line shows the compensated distance as `motion:`.
- Fixed muzzle flash and smoke appearing on the wrong part of the vehicle (wheels, hull, suspension) when the gun was aimed down or close to the hull.
- Fixed flashes attaching to the wrong barrel while the vehicle is moving fast with the turret turned.
- Fixed vehicles with two guns on one turret (for example BMD-4M) mixing up which barrel the flash appears on.
- Fixed a wrong barrel getting "stuck": once the addon picked a wrong spot at a given turret angle, it kept using it for every following shot.
- Fixed ammo rack fire flickering out after two seconds while the rack is still burning — it now burns as one steady fire until LVS puts it out.
- Fixed heavy frame drops when driving on water — the spray no longer starts a new effect every tick for every wheel.
- Fixed effects sometimes being created twice per shot after a Lua reload.
- Fixed fire, ammo-rack and trail effects being restarted every frame instead of once.

**Changed**
- Tracers are Gredwitch's own tracer particles flying LVS ballistics. The addon ships `particles/lvs_gred_tracers.pcf`, generated from gred's tracer definitions by `tools/pcf_tool.py` (same streak, colours, smoke and glow children); the fixed-speed launcher is replaced by a previous-position remap so the particle leaves at the LVS round's own velocity, with gravity matched to LVS's ballistic flight. Players without this addon still get the straight gred beam from the server, now using the gred definition whose baked-in speed is closest to the round's.
- Which barrel a gun fires from is now read from the vehicle's own LVS weapon setup: the attachment named in the weapon's fire code is used when the shot really leaves from it, and multi-barrel guns (`"muzzle_" .. n`) are narrowed down by the line of fire. Twin and quad mounts whose code names one shared point and offsets each barrel from it are detected and resolved to the actual barrel instead of all flashing from that one point.
- Smoke canisters now use the Gredwitch smoke cloud, refreshed every 3 seconds while the canister is active so it never piles up or lingers after it's spent.
- Barrel detection now follows the line of fire: the barrel point that lies along the direction the shot went is chosen, instead of whichever point is simply nearest. Recoiled barrels, side-by-side barrels and sights next to the gun no longer confuse it.
- Cannon barrel smoke now plays in two stages: the sharp white burst first, and the lingering smoke only starts once the burst has finished. No more overlapping clouds.
- Attachment detection is now checked against a still copy of the vehicle instead of the moving one, so vehicle speed no longer affects where effects appear.
- Tracer path calculation on the server is lighter (half the trace work per machine-gun round).

**Added**
- Each gun on a vehicle remembers which barrel point it uses after its first shot, so a recoiling barrel or a turning turret can't make later shots jump to a different spot.
- Debug output now shows the real attachment name and how far it was from the shot, making problems easy to report.

**Removed**
- Removed the old "remembered barrel position" shortcut that caused stuck wrong barrels.
